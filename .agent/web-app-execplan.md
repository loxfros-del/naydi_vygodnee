## Purpose / Big Picture

После первого этапа у «Найди выгоднее» появится установленное на телефон и открываемое в браузере веб-приложение. Человек сможет начать бесплатный подбор, ответить на те же базовые вопросы, получить сохранённую на устройстве заявку и посмотреть пример безопасного отчёта с понятной экономией в рублях. Это даст команде готовый интерфейс для согласования дизайна до подключения серверного API. Telegram-бот, SQLite-база и `main.py` не изменяются.

- Observation: в репозитории нет веб-сервера или frontend-сборщика.
  Evidence: `requirements.txt` содержит Telegram- и поисковые библиотеки, но не HTTP framework или Node-зависимости.
- Observation: заявки уже создаются через не зависящий от Telegram фасад `RequestService.create_from_payload`.

  Rationale: это даёт проверяемый интерфейс без риска для работающего Telegram MVP, ручной оплаты и SQLite-схемы; серверный API будет отдельным обратимо подключаемым milestone.
  Date/Author: 2026-08-13 / Codex.
- Decision: оставить все пакеты бесплатными до подтверждения возвращаемости пользователей и качества поиска.
  Rationale: основная ценность на текущем этапе — стабильно находить тот же товар дешевле рынка и понятно доказывать выгоду, а не строить платёжную воронку.
  Date/Author: 2026-08-13 / Codex.
- Decision: PWA сохраняет черновики и демонстрационные заявки только в `localStorage` браузера и явно не утверждает, что отправила их в работу.
  Rationale: без API нельзя создавать настоящую заявку. Такое хранение безопасно и исключает ложное обещание пользователю.
  Date/Author: 2026-08-13 / Codex.

## Outcomes & Retrospective

Первый PWA-MVP создан. В нём есть жёлто-чёрная минималистичная главная, бесплатный подбор, мастер из четырёх шагов, честное локальное хранение черновиков и пример безопасного отчёта из трёх клиентских ролей. Проверка браузером показала отсутствие console errors и горизонтальной прокрутки на ширине 360 px. Telegram-бот, `main.py`, SQLite-схема и `.env` не менялись. В бесплатном режиме админ утверждает только готовый результат, после чего использует существующую защищённую отправку полного отчёта; новый клиент не попадает в этап ожидания оплаты. Следующий результат плана — API adapter и авторизация; до него PWA не запускает настоящий поиск и не создаёт заявки в рабочей очереди.

## Context and Orientation

Проект — Telegram-бот на Python. `app/product_config.py` содержит пакеты услуг и уже читает переопределения цен из переменных окружения; он не импортирует секреты. `app/services/request_wizard.py` — чистая модель вопросов заявки, а `app/services/product_services.py` создаёт заявку из payload. `app/ui_formatters.py` задаёт безопасные клиентские роли и статусные тексты. `main.py` запускает только Telegram-бот и по запрету проекта не изменяется.

Новый каталог `web/` будет статическим PWA (Progressive Web App): это обычный сайт, который современный браузер может установить на главный экран. Его файлы открываются с локального HTTP-сервера; PWA сохраняет оболочку для работы без сети. На первом этапе он не выполняет сетевые запросы и не пишет в SQLite.

## Plan of Work

Создать `web/index.html`, `web/styles.css` и `web/app.js`. Страница будет содержать единственный спокойный интерфейс с логотипом, стартовым экраном, мастером из четырёх шагов, сводкой, экраном сохранённой заявки и демонстрационным отчётом. Все основные действия должны быть доступны с клавиатуры и на экране шириной от 320 пикселей. Чёрный — основной фон, жёлтый служит только для ключевой цены, CTA и статуса выгоды, а не для каждого элемента.

В `web/app.js` создать локальное состояние мастера и сохранить созданную демо-заявку в `localStorage` под namespaced-ключом. Успешное окончание мастера должно отображать честный текст «Заявка сохранена на этом устройстве» до появления API. Отчёт показывает только три клиентские роли: лучший выбор, бюджетный вариант и стоит проверить, без внутренних score, технических статусов и ложных ссылок.

Добавить `web/manifest.webmanifest` и `web/service-worker.js`, чтобы оболочка могла устанавливаться. Добавить `web/README.md` с командами запуска через стандартный Python HTTP server и с объяснением границы первого этапа. В `app/product_config.py` закрепить бесплатный публичный запуск: все пакеты возвращают цену ноль, а старые переменные цен игнорируются до отдельного решения о монетизации.

Создать `tools/test_web_app.py`: тест должен читать статические файлы и доказать присутствие manifest, service worker, бесплатного статуса, основных экранов и отсутствия сетевых вызовов. Он не открывает `bot.db` и не требует браузера.

Во втором этапе добавить отдельный HTTP adapter, не изменяя доменную логику: endpoint аутентифицирует пользователя Telegram Login, передаёт валидированный payload в `RequestService.create_from_payload`, читает заявки через `db.get_user_requests`, а результат строит существующим presentation layer. До этого этапа нельзя называть локально сохранённую запись оформленной заявкой.

## Validation and Acceptance

На экране 320px нельзя увидеть горизонтальную прокрутку, обрезанные кнопки или наложившийся текст. Пользователь нажимает «Начать подбор», выбирает категорию, описывает товар, указывает бюджет и город, выбирает приоритет и видит сводку. После «Сохранить черновик» приложение создаёт карточку с номером и пометкой локального хранения. Экран «Пример результата» показывает цену, выгоду, риски и роли, но не выдаёт sample-карточки за реальный поиск.

`tools/test_web_app.py` должен завершиться успешно и гарантировать, что PWA-файлы ссылаются друг на друга, бесплатный статус и основные фразы интерфейса присутствуют, а `app.js` не содержит `fetch`, `XMLHttpRequest` или `WebSocket`.

## Idempotence and Recovery

Статические файлы можно перезаписывать и раздавать повторно. Чтобы сбросить только демонстрационные записи конкретного браузера, пользователь очищает данные сайта в настройках браузера; репозиторий, `.env` и базы данных не затрагиваются. Удалять или изменять существующие SQLite-файлы не требуется.
