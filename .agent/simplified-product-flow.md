# Упростить подбор товара и админскую проверку

Этот ExecPlan является живым документом. Он ведётся по правилам `.agent/PLANS.md`.

## Purpose / Big Picture

После выполнения клиент сможет создать заявку без обязательных лишних вопросов, а администратор увидит короткий рабочий путь: запустить поиск, открыть до трёх пригодных вариантов, утвердить роли и отправить отчёт. Поиск через Yandex Search API будет использовать чистые запросы с назначением товара, а неподходящие результаты не будут маскироваться под хорошие.

- Observation: Search API работает и списывает средства, но поисковый запрос «ноутбук» без назначения возвращает неигровые модели.
  Evidence: заявка #38 содержала Celeron N4000/N5095, а Debug показал запрос Yandex API «ноутбук».
- Observation: Telegram не отправляет Debug длиннее 4096 символов.
  Evidence: `TelegramBadRequest: message is too long`; отчёт уже разделён на части.

## Context and Orientation

`app/services/request_wizard.py` описывает шаги клиентского мастера. `app/ui_keyboards.py` строит клавиатуры мастера. `app/keyboards.py` строит админские кнопки. `app/product_search.py` формирует запросы, принимает результаты и отбрасывает неподходящие карточки. `app/candidate_verifier.py` пытается подтвердить открытие страницы и цену.

## Plan of Work

Сначала будут добавлены явные кнопки пропуска только для необязательных вопросов мастера. Затем `kb_admin_request` будет оставлять в основном состоянии только поиск, варианты, ручное добавление, предпросмотр и оплату; служебные функции останутся доступны через отдельную кнопку «Дополнительно». После этого поиск будет очищать и дедуплицировать результаты до показа: одна ссылка или одна и та же модель у одного продавца должна оставаться один раз. Для игровых ноутбуков будут отклоняться слабые CPU независимо от источника.

## Validation and Acceptance

Клиент может нажать «Пропустить» на вопросах о цвете, дополнительных требованиях и подобных необязательных деталях. Админ при открытии заявки видит не более пяти основных действий. В выдаче игрового ноутбука не остаются N4000, Celeron, N95, N100 и N5095; одинаковая карточка не повторяется. Подтверждённые или требующие ручной проверки ссылки остаются различимыми.

## Idempotence and Recovery

Правки не меняют схему SQLite, оплату, кредиты, `.env` или `main.py`. Тесты можно запускать повторно. При ошибке поиска повторная заявка создаёт новую независимую диагностику.
