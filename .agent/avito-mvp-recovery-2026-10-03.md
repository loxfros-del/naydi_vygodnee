# Довести Avito PS5 до проверяемого MVP

This ExecPlan is a living document. Maintain it under `.agent/PLANS.md`. `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must reflect the actual state after each milestone.

## Purpose / Big Picture

Покупатель в Ярославле вводит PS5 и получает проверенные совпадения с прямой ссылкой, актуальной ценой и понятной пометкой об экономии либо её отсутствии. Продавца и скрытые технические дефекты покупатель проверяет при встрече. Владелец видит причины отказа каждого близкого объявления и расход поиска. После первого остановленного лимитом запуска владелец 03.10 выделил остаток $8 на доведение финалистов; каждый следующий платный шаг ограничен фактическим остатком аккаунта.

## Surprises & Discoveries

- `runtime/avito_pilot/aitunnel-log-observation-20261003.json` сохраняет только вывод по разрешённому интервалу, без ключей и посторонних данных аккаунта. Live логи доступны лишь при открытой вкладке захвата и не сохраняются на сервере — историческую ошибку здесь получить нельзя. Запуск нового захвата не требуется для чтения прошлого запроса и не выполнялся.
- `runtime/avito_pilot/aitunnel-client-compare-20261003.json`: разметка фаз одноразового GET точно показала TCP→тайм-аут TLS. Это доказательство фазы нового бесплатного сбоя, но не ретроспективное доказательство доставки или недоставки предыдущего платного POST. Резерв поэтому остаётся неопределённым.
- Официальная документация AITUNNEL на 03.10.2026 описывает зеркало `https://ru-api.aitunnel.ru/v1` для сбоев соединения: https://aitunnel.ru/docs/errors. Старый код распознавал особенности AITUNNEL (профиль модели и SSE/usage) только по `api.aitunnel.ru`; теперь оба точных hostname получают одинаковое поведение без автоматической смены адреса. Бесплатные прямые GET обоих хостов без токена в 16:21 UTC завершились TimeoutError примерно за 10 секунд; это не доказательство работоспособности зеркала. Артефакт: `runtime/avito_pilot/aitunnel-mirror-free-check-20261003.json`.
- Публичный справочник https://aitunnel.ru/docs/api-reference и https://aitunnel.ru/docs/api/stats описывает агрегированную статистику, не получение статуса/стоимости отдельного синхронного chat/completions. Агрегаты не могут служить квитанцией конкретного повтора; недокументированные endpoints не перебирались.
- Бесплатная диагностика 15:56–15:57 UTC установила различие маршрутов: системный urllib использует Windows proxy 127.0.0.1:10809 и завершает GET SSLEOFError; прямая TLS-проверка успешна, прямой urllib GET с проверкой сертификата вернул HTTP 401 без токена менее чем за секунду. Выбран прямой маршрут только AI-клиента; системные настройки и TLS-проверка не меняются. Однако последующий фото POST завершился тайм-аутом: успешный GET не доказывает исправность платного фотоанализа.
- Единственный разрешённый повтор сохранён в `runtime/avito_pilot/recheck-20261003T160208292756Z/result.json`. `opening_response` включает соединение, TLS, отправку и ожидание заголовков; по этому trace точная фаза сбоя не установлена. Последующие поля длительности/маршрута не приписаны историческому результату.
- Бесплатные HEAD девяти исходных URL в 16:09–16:11 UTC: direct дал 1 HTTP 200 и 8 TimeoutError; system дал 2 HTTP 200 и 7 TimeoutError. Это показывает нестабильную доступность изображений с локального компьютера, но не доказывает, как их получает AITUNNEL. Пакет содержит 9 разных HTTPS URL, detail=high, около 13 КБ JSON. Фото в AI повторно не передавались. Артефакты: `photo-url-headers-20261003.json`, `photo-url-headers-system-20261003.json` в `runtime/avito_pilot/`.

- Trace `pilot-20261003T131320Z.json` завершился `UnicodeEncodeError` при печати в консоль, хотя `report.json` и `audit.json` уже сохранены. Null-поля trace не доказывают отсутствие работы; воронка восстанавливается по audit. Исправление должно сохранять итог до вывода в Windows-консоль.
- Четыре попытки фото в audit не означают четыре сетевых POST: два кандидата были остановлены AI-бюджетом до отправки; один получил сетевой сбой, один — полный caution. Старый service оценивал сетевой сбой долей оставшегося бюджета вместо сохранённого резерва. Первоначальная гипотеза о начислении этой суммы бюджет-блокам не подтвердилась: их перехватывал `_review_photos_one`. Исторические оценки фото не являются квитанцией или точной суммой резервов.
- Старый `recheck-20261003T132842Z/result.json` содержит только начало фото без ответа и стоимости. Отсутствие записанного расхода не означает нулевое списание. По текущему неизменному снимку резерв повторного пакета — 31.78 ₽; это расчёт, не фактическая стоимость предыдущей попытки.
- Бесплатные пробы 15:25 UTC: TCP успешен; отдельные TLS и GET без токена завершились TimeoutError и SSLEOFError до HTTP. Конкретный виновник маршрута не доказан, но постоянная ошибка авторизации из этих данных не следует.
- Подтверждённые usage AI старого поиска — 3.47 ₽; прежний общий учёт 30.9467 ₽ содержит 9.5267 ₽ ошибочной оценки сетевого фото. Старый recheck имеет дополнительный неизвестный расход. Полный разбор: `docs/avito_mvp_checkpoint_2026-10-03.md`.

## Decision Log

- Decision: Выполнить один явно разрешённый повтор девяти фото; работу с Render отложить. Rationale: новое прямое сообщение владельца. Date/Author: 2026-10-03, owner.
- Decision: Выбрать ai_proxy_mode=direct для профиля AITUNNEL до платного POST, без сетевого fallback/retry и без изменения Windows proxy. Rationale: сравнительный бесплатный GET через системный proxy упал с SSLEOFError, прямой получил HTTP 401; сертификат проверяется штатно. Date/Author: 2026-10-03, agent.

- Decision: Отказ автоматической проверки повторной передачи девяти фото не обходить: сначала офлайн-работа, затем отдельное явное согласие владельца именно на этот повтор. Rationale: прямое ограничение пользователя в текущем сообщении. Date/Author: 2026-10-03, owner.
- Decision: Не сбрасывать неизвестный расход при сетевом обрыве, сохранять запись до POST; заблокированный до POST вызов учитывать как нулевой новый расход. Rationale: резерв отличается от квитанции и должен пережить сбой процесса. Date/Author: 2026-10-03, agent.
- Decision: Готовность MVP требует безопасного live-финалиста, проверенного пользовательского сценария и внешней HTTPS-ссылки одновременно. Отдельные тесты и Blueprint этого не доказывают. Rationale: уточнение владельца в текущем сообщении. Date/Author: 2026-10-03, owner.
- Decision: Исторические pending Apify допускается перевести только в settled_estimate после полного доказательства отсутствия незавершённых run, без снижения сумм и без присвоения индивидуальной квитанции. Date/Author: 2026-10-03, agent.

- Decision: Для пользовательского MVP требуется внешняя HTTPS-ссылка. Rationale: прямой ответ владельца 2026-10-03. Date/Author: 2026-10-03, owner.

## Validation and Acceptance

На сохранённой выборке тесты объясняют судьбу каждого фото-проверенного объявления. Исправленный сервис не теряет PS5 за 44 000 ₽ до фото только из-за рейтинга продавца; он не выдаёт его клиенту до полной проверки. При частичном ответе финального Actor только действительно совпавшие и неизменившиеся URL могут получить статус verified. Клиентская карточка без трёх аналогов явно говорит «выгода не подтверждена» и не содержит чисел экономии. Live trace должен показывать полную воронку, количество прямых URL на финале, количество ответов и причины отсутствия карточек. Успех клиентского MVP требует хотя бы одного реально проверенного точного PS5 в выдаче, работающего пользовательского сценария и доступной внешней HTTPS-ссылки. Если источник не подтверждает ни одного товара, результат честно пустой и MVP ещё не готов.

## Idempotence and Recovery

Офлайн-чтение и тесты повторяемы и бесплатны. Если платный запуск не создаст run, освободить доказанно неиспользованный резерв; при неопределённом исходе сохранить консервативный учёт. Повторный paid POST автоматически запрещён. Если live поиск опять пуст, использовать trace и завершить диагностику без второго запуска.
