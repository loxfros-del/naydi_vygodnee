# AGENTS.md

## Проект

`Найди выгоднее` — Telegram-бот подбора выгодных товаров. Сценарий: клиентский запрос -> заявка -> админ -> Gemini/Алиса -> карточки -> роли ТОП-1/запасной/бюджетный/осторожно -> предпросмотр -> оплата -> полный отчёт.

## Главная продуктовая цель

- Главный результат — точный товар дешевле сопоставимого рынка, который можно заказать на момент проверки.
- «Ниже рынка» разрешено писать только после сравнения той же модели, комплектации и состояния по нескольким независимым предложениям.
- Цена, прямая товарная ссылка, наличие и возможность заказа должны быть подтверждены непосредственно перед выдачей; абсолютную гарантию будущего остатка не обещать.
- Если подтверждённого предложения ниже рынка нет, не выдумывать выгоду и не ослаблять проверки. Показывать надёжный запасной вариант без ярлыка «ниже рынка».
- Для надёжного запасного варианта сначала проверять DNS, затем другие крупные магазины с понятными возвратом и гарантией. DNS не считать автоматически лучшим без проверки цены, наличия и условий.
- Количество заявок — средство проверки ядра. Качество, реальная выгода и возможность заказа важнее числа обработанных заявок.

## Запреты

- Не трогать `.env`, `.venv`, `bot.db`, `*.db`.
- Не менять Telegram token.
- Не менять `main.py` без прямого запроса.
- Не ломать SQLite-схему, оплату и кредиты.
- Не переписывать проект целиком.
- Не менять `app`-код, если задача про инструкции, агентов, промты или безопасные проверки.

## Роли отчёта

- `BEST` / `TOP` / `TOP1` = ТОП-1.
- `BACKUP` / `APPROVED_BACKUP` = запасной.
- `BUDGET` / `APPROVED_BUDGET` = бюджетный.
- `DO_NOT_BUY` / `CAUTION` = осторожно.
- `REJECTED` / `REJECTED_AUTO` не показывать клиенту.

## Правила парсера

- URL не должен становиться отдельной карточкой.
- Любая правка парсера Gemini/Алисы требует теста в `tools/test_alice_parser.py`.

```bash
python tools/test_alice_parser.py
```
