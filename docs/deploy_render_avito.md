# Закрытый Avito пилот на Render

`render.yaml` описывает только отдельный Avito веб-сервис. Telegram-бот, его база и оплата не размещаются через этот файл.

1. Подключить [GitHub-репозиторий](https://github.com/loxfros-del/naydi_vygodnee) к Render и создать Blueprint из `render.yaml` на ветке `codex/all-work-2026-10-02` после публикации проверенного коммита. Сверить SHA в Render с проверенной версией: новые локальные исправления не входят автоматически в ранее опубликованный `b2f6cb1`.
2. Render запросит `APIFY_TOKEN`, `AVITO_AI_API_KEY`, `AVITO_AI_BASE_URL`, `AVITO_AI_MODEL`, `AVITO_ACCESS_TOKEN` и `AVITO_OWNER_TOKEN`. Ввести их только в панели Render. Для AI Tunnel штатный профиль задаёт модель `gpt-4.1-mini`; её же можно указать в панели. Ключи доступа и владельца должны быть разными, каждый не короче 32 случайных символов. Тестировщикам передавать только ключ доступа.
3. Первый запуск выполнить без рабочего `APIFY_TOKEN`, чтобы случайное нажатие не создало платный run. Проверить постоянный диск `/opt/render/project/src/runtime`. Остановить локальные платные поиски, сохранить резервную копию и перенести действующий `runtime/avito_spend.json` на этот диск через закрытый канал управления Render; не коммитить `runtime/` и не публиковать журнал в URL. Сверить SHA-256 локальной и серверной копий. Не создавать пустой журнал взамен существующего и не удалять неподтверждённые резервы: отсутствующий файл сейчас означает нулевой учёт, а не запрет расходов.
4. В shell Render прочитать состояние без сетевых запросов:

   ```bash
   python -c "from pathlib import Path; from avito_service.spending import SpendingGuard; print(SpendingGuard(Path('runtime/avito_spend.json'), daily_limit_usd=3, billing_cycle_day=9).snapshot())"
   ```

   Команда показывает подтверждённый расход, оценки и активные резервы отдельно. Перезапустить сервис и повторить чтение: состояние должно сохраниться. По свежему бесплатному `GET /v2/users/me/limits` и квитанциям конкретных Apify run сверить реальный остаток. Не подменять неизвестный расход нулём, не считать агрегат аккаунта квитанцией конкретного run и не повышать hard limit. При расхождении журнала и аккаунта оставить поиск закрытым до сверки. Локальный и размещённый сервис не должны параллельно расходовать один аккаунт с раздельными журналами.
5. Только после сверки учёта добавить рабочий `APIFY_TOKEN`. Открыть `/health`: `ready.apify` и `ready.ai` должны быть `true`. Это проверяет заполненность конфигурации, а не доступность провайдеров, остаток денег или качество финалистов. До приглашения участников бесплатно проверить: `/api/session` без ключа возвращает 401; ключ участника возвращает `owner: false`, отдельный ключ владельца — `owner: true`; `POST /api/avito/analyze-dataset` с ключом участника возвращает 401 до обращения к AI. Ключи не передавать в URL.
6. После публикации использовать выданный Render адрес `https://…onrender.com/`. Участники входят с `AVITO_ACCESS_TOKEN`; владелец использует отдельный `AVITO_OWNER_TOKEN`. Автоматическое развёртывание выключено, чтобы новая версия не сбрасывала выполняемую задачу без ведома владельца. Очередь задач пока хранится в памяти: перезапуск сохраняет журнал расходов, но не восстанавливает job; перед развёртыванием дождаться завершения активного поиска. При потере соединения не повторять платный POST автоматически.

Blueprint предусматривает платный веб-экземпляр и постоянный диск. Бесплатный экземпляр с временной файловой системой не подходит для журнала расходов Apify. Выделенные 03.10.2026 $8 на продолжение поиска не означают согласие на отдельную подписку хостинга: владелец подтверждает тариф в Render перед созданием сервиса. Сам файл Blueprint не создаёт сервис и не списывает деньги.

Публичная ссылка подтверждает доступ к интерфейсу, но не подтверждает качество выдачи. До приглашения людей выполнить один контролируемый live-поиск, проверить прямые ссылки, актуальность цен, причины отказа и итоговый расход. При отсутствии завершённой проверки карточка остаётся вне выдачи.

На 03.10.2026 внешний адрес и созданный сервис ещё не подтверждены. Автоматические проверки HTTP-сценария и безопасности выполняются на loopback с фикстурами: `python -B -m unittest tools.test_avito_web_mvp tools.test_avito_ops_quality tools.test_avito_server_binding -q`. Они не расходуют Apify/AI и не доказывают доступность Render. Для первого теста на людях нужен завершённый PS5-сценарий: Ярославль, самовывоз, все фото проверены, цена и активность страницы обновлены; при недостатке аналогов карточка не обещает экономию.
