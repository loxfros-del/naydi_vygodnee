# Закрытый Avito пилот на Render

`render.yaml` описывает только отдельный Avito веб-сервис. Telegram-бот, его база и оплата не размещаются через этот файл.

1. Подключить GitHub-репозиторий к Render и создать Blueprint из `render.yaml` на ветке `codex/all-work-2026-10-02` после публикации проверенного коммита.
2. Render запросит `APIFY_TOKEN`, `AVITO_AI_API_KEY`, `AVITO_AI_BASE_URL`, `AVITO_AI_MODEL`, `AVITO_ACCESS_TOKEN` и `AVITO_OWNER_TOKEN`. Ввести их только в панели Render. Для AI Tunnel штатный профиль задаёт модель `gpt-4.1-mini`; её же можно указать в панели. Ключи доступа и владельца должны быть разными, каждый не короче 32 случайных символов. Тестировщикам передавать только ключ доступа.
3. Перед первым платным поиском открыть `/health`: `ready.apify` и `ready.ai` должны быть `true`. Проверить, что постоянный диск смонтирован в `runtime/`, а журнал `avito_spend.json` сохраняется после перезапуска. Старый локальный журнал на новый сервер автоматически не переносится: сверить текущие расходы в Apify и задать исходный учёт через предусмотренную безопасную процедуру, прежде чем давать доступ к поиску.
4. После публикации использовать выданный Render адрес `https://…onrender.com/`. Участники входят с `AVITO_ACCESS_TOKEN`; владелец использует отдельный `AVITO_OWNER_TOKEN`. Автоматическое развёртывание выключено, чтобы новая версия не сбрасывала выполняемую задачу без ведома владельца.

Render требует платный веб-экземпляр для постоянного диска. Бесплатный экземпляр с временной файловой системой не подходит для журнала расходов Apify. Платный хостинг оплачивается отдельно от лимита 300 ₽ на один контрольный поиск. Сам Blueprint не создаёт сервис и не списывает деньги до его запуска в Render.

Публичная ссылка подтверждает доступ к интерфейсу, но не подтверждает качество выдачи. До приглашения людей выполнить один контролируемый live-поиск, проверить прямые ссылки, актуальность цен, причины отказа и итоговый расход. При отсутствии завершённой проверки карточка остаётся вне выдачи.
