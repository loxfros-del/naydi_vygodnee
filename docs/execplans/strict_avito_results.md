# Точная и доказанная выдача Avito без подстановки других товаров

План следует `.agent/PLANS.md` и обновляется по ходу работы.

## Purpose / Big Picture

После запроса владельца от 13.09.2026 PS5 не должен приводить к показу PS4 даже с меткой «есть отличия». Режим «Найти выгоднее» выдаёт только проверенные подходящие предложения с подтверждённой выгодой; «Найти точно» — проверенные совпадения. Количество 3/5 является максимумом. Если подходящих результатов нет, показывается одна понятная причина, без заполнения списка неподходящими объявлениями.

## Surprises & Discoveries

Скриншот показывает не ложное признание PS4 точной PS5, а намеренное заполнение отсутствующих рекомендаций через `avito_service/discovery.py`. Предыдущее правило владельца от 09.09.2026 разрешало это, но нынешнее явно отменяет его. `matches_listing_request` на предварительном этапе не проверял модель. `apify.collect` запрашивал cheapest ещё до собственного отсева. UI показывает только число скрытых фильтров; после смены запроса могут остаться требования из старого примера.

## Outcomes & Retrospective

Исправление поведения подтверждено на воспроизводимых данных: PS4 из скриншота не попадает в публичный ответ по запросу PS5, одна проверенная выгодная PS5 остаётся одной карточкой. Сценарии проходят через реальный локальный HTTP API и настоящий JS-рендерер в VM. Полный набор Avito: 282 теста, OK. Оба JS-теста и проверка синтаксиса прошли после последнего изменения; исходный Alice parser и компиляция тоже прошли. Браузер недоступен через CUA, визуальное подтверждение не получено. Конкретная выгодная PS5 на сегодняшнем рынке этими тестами не подтверждается; платного сбора в этой задаче не было. Инструкции и база знаний синхронизированы, итоговый отчёт сохранён.

Полный прогон обнаружил также гонку Windows-блокировки расходов: запись нулевого байта до захвата блокировки могла приводить к PermissionError. Удалена только эта ненужная запись; блокировка за концом файла разрешена Microsoft. Добавлена детерминированная межпроцессная регрессия. Лимиты и учёт резервов сохранены.

## Context and Orientation

`avito_service/matching.py` проверяет модель и требования. `apify.py` формирует внешний поисковый запрос. `service.py` собирает рынок, анализирует кандидатов и обновляет финалистов. `models.AnalysisReport` сериализует публичный и административный результат; здесь нужен последний обязательный фильтр. `jobs.py` хранит готовые отчёты в памяти. `avito_web/app.js` показывает результаты и восстанавливает сохранённую задачу. `discoveredListings` — диагностические найденные карточки, а не рекомендации; в публичном ответе теперь пустой список.

В `apify.py` получать первичный набор по релевантности, затем ранжировать цену локально после совпадения. Подходящие карточки из уже оплаченной рыночной выборки могут быть кандидатами с дальнейшим полным анализом и обновлением; нельзя просто переименовать их в проверенные. UI принимает только `resultPolicy` текущей версии, не восстанавливает ошибочную старую выдачу и не запускает новые платные запросы автоматически. Описания 3/5 и пустого результата соответствуют фактическому допуску.

## Idempotence and Recovery

Новые проверки не используют секретов, сетевого сбора или файловых баз. Исходные ошибочные карточки сохраняются для диагностики. Кэш ключа анализа/рынка меняется для новой политики, а старые сохранённые UI-результаты требуют явного нового поиска. Не удалять runtime и не сбрасывать лимиты ради тестов. При откате удалять только изменения этой задачи, не сбрасывать рабочее дерево.
